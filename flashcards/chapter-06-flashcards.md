## Chapter 6: Applying Generative AI: Prompting, RAG, and Embeddings — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | RAG vs Fine-tuning: use RAG when... | Knowledge changes frequently, you need citations/source grounding, or you want to reduce hallucination on facts. Exam tip: RAG = dynamic knowledge injection without retraining. |
| 2 | RAG vs Fine-tuning: use Fine-tuning when... | You need to change tone, style, output format, or teach a narrow behavior/skill — NOT to reliably add new facts. Exam tip: fine-tuning shapes behavior, RAG supplies knowledge. |
| 3 | Zero-shot vs Few-shot vs Chain-of-thought — core difference? | Zero-shot: no examples, just instructions. Few-shot: includes labeled input/output examples to anchor format/behavior. Chain-of-thought: prompts the model to reason step-by-step before answering. Exam tip: match technique to task need (format consistency = few-shot, multi-step logic = CoT). |
| 4 | Standard RAG pipeline order (5 stages)? | 1) Chunk source documents 2) Embed chunks into vectors 3) Store vectors in a vector index 4) At query time, embed the query and retrieve top-k similar chunks 5) Augment the prompt with retrieved chunks and generate the answer. Exam tip: retrieval happens BEFORE generation, not after. |
| 5 | What does 'top-k retrieval' mean in RAG? | Returning the k most similar vector matches to the query embedding (e.g., top 3-5 chunks) to include as context for the generation step. Exam tip: too small k risks missing context; too large k increases cost/latency and noise. |
| 6 | What similarity metric is the default for comparing text embedding vectors? | Cosine similarity (range -1 to 1, closer to 1 = more similar). Exam tip: it measures vector angle, not magnitude, so it's robust to text length differences. |
| 7 | Hybrid search in a vector/search service combines what three elements? | Vector (semantic/dense) search + keyword (sparse/lexical) search + a semantic re-ranker on top. Exam tip: hybrid search generally outperforms vector-only search for RAG retrieval quality. |
| 8 | What index structure/algorithm is commonly used for fast approximate vector similarity search at scale? | HNSW (Hierarchical Navigable Small World) graphs — used by most production vector databases for approximate nearest-neighbor (ANN) search. Exam tip: ANN trades a small accuracy loss for large speed gains vs exact search. |
| 9 | Diffusion model generation process in one sentence? | Starts from random noise and iteratively denoises it over many steps, conditioned on a text embedding, until a coherent image forms. Exam tip: it's an iterative reverse-noising process, not a single-pass transformation. |
| 10 | GenAI product design tradeoff: smaller/distilled model vs larger flagship model? | Smaller models (e.g., 'mini' tier) have lower latency and lower cost but weaker reasoning; larger flagship models have higher quality but higher latency and cost. Exam tip: match model size to the task's accuracy requirement, don't over-provision. |
| 11 | Three key risks to evaluate when designing a GenAI product? | Latency (response time), cost (tokens/compute per request), and hallucination risk (ungrounded/fabricated outputs). Exam tip: RAG primarily mitigates hallucination risk, not latency or cost. |
| 12 | Why does chunk size matter when preparing documents for a RAG vector index? | Chunks too large dilute embedding relevance and waste context window; chunks too small lose surrounding context. Common practice: moderate-size chunks with slight overlap between consecutive chunks. Exam tip: chunking strategy directly affects retrieval accuracy. |
